# 구조와 데이터 계약

## 책임

```text
app/                         라우트, 메타데이터, HTTP 처리
app/actions/                 검증 → 인증 → DB 변경 → 경로 재검증
components/{questions,answers,auth,layout,ui}/
                             기능 UI 및 작은 공유 UI
lib/validation/              순수 입력 파서와 검색 URL 생성
lib/auth/                    인증 클라이언트와 내부 리다이렉트 검증
lib/queries/                 서버 전용 화면별 읽기 모델
lib/supabase/                환경별 클라이언트·쿠키 어댑터
types/database.types.ts      실제 마이그레이션에서 자동 생성된 DB 타입
types/models.ts              화면에 필요한 모델
types/actions.ts             폼·변경 결과의 구분 가능한 상태
supabase/migrations/         스키마·권한·데이터 불변조건
```

데이터 함수는 데이터 또는 `null`을 반환하고 페이지에서 `notFound()`·리다이렉트를 결정합니다. 예상되는 액션 실패는 `ActionState`로 반환합니다. 리다이렉트는 일반 오류 catch 밖에서 실행합니다.

질문 상세와 메타데이터는 요청 범위의 `React.cache`로 질문 조회를 공유합니다. 편집은 질문 필드와 태그만, 답변은 별도 페이지 단위로, 인기는 네 필드만 조회합니다. 생성된 뷰 타입의 nullable 필드는 매핑 경계에서 검증합니다.

## DB 규칙

- RLS는 행의 소유권을, 컬럼 권한은 수정 가능 필드를 제한합니다.
- TypeScript `Insert/Update` 타입은 DB 구조 표현이며 권한 통제가 아닙니다.
- 질문과 태그 변경은 하나의 트랜잭션 RPC입니다.
- 태그 최대 5개 규칙은 직접 API 삽입에도 적용됩니다. 부모 질문 잠금 후 개수를 검사합니다.
- 답변 상태는 답변 개수에서 계산합니다. 별도의 상태 동기화 트리거는 없습니다.
- 답변은 생성 후 다른 질문으로 옮길 수 없습니다.
- 조회수는 원자적 카운터이고 질문 편집 시각을 바꾸지 않습니다.
- 검색은 매개변수 기반 리터럴 검색입니다. `%`, `_`, 쉼표, 괄호를 사용자 몰래 제거하지 않습니다.
- 목록은 20개 단위, 마지막 확인용 1개 추가 조회로 `hasMore`를 구합니다. 정렬값이 같으면 ID로 정렬합니다.

페이지 번호 방식이므로 실시간 추가·삭제나 조회수 변경 중 여러 페이지를 탐색하면 위치가 바뀔 수 있습니다. 일관된 시점의 스냅샷 탐색을 보장하는 제품은 아닙니다.

## 조회수 의미

상세 화면의 클라이언트 마운트에서 방문 카운터를 호출합니다. RSC 렌더나 링크 프리페치가 조회수를 직접 변경하지 않습니다. 익명 RPC가 허용되어 있으므로 중복 방문·봇·직접 호출을 배제한 고유 방문자 통계가 아닌 **대략적인 방문 지표**입니다.

## 스타일·재사용

전역 CSS는 디자인 토큰·페이지 레이아웃과 기존 화면 스타일을 담당합니다. 인증 카드와 확인창은 CSS Modules로 범위를 제한했습니다. 새로운 기능 스타일도 모듈을 기본으로 하며 나머지 전역 스타일은 화면 변경 시 점진적으로 이동합니다.

홈과 목록 라우트의 짧은 조합, 서버/프록시의 서로 다른 쿠키 어댑터는 의도적인 분리입니다. 폼 결과, 답변 검증, 필터 URL, 경로 재검증은 공통화했습니다. 사용되지 않던 브라우저 Supabase 어댑터와 단건 답변 조회는 제거·대체했습니다.

## 검증 경계

- 단위 테스트: 런타임 입력·리다이렉트·URL·시간 처리
- PostgreSQL 통합 테스트: 실제 RLS·컬럼 권한·마이그레이션·트랜잭션·동시성·페이지네이션·타입 드리프트
- Playwright 스모크: 실제 프로덕션 Next 서버의 인증 UI·아이콘·오류 경계·모바일·접근성
- Supabase E2E: 실제 Auth/PostgREST를 사용하는 로그인·CRUD·확인 토큰·모바일 로그아웃

PostgreSQL 통합 테스트의 `auth.users`/`auth.uid()`는 최소 테스트 어댑터입니다. GoTrue·PostgREST·실제 메일 배달을 대신 검증한다고 간주하지 않습니다. Supabase E2E의 확인 토큰은 admin API에서 생성하므로 메일 발송업체의 실제 배달 여부는 별도 확인합니다.
